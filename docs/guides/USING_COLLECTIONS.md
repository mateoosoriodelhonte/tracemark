# Use collections effectively

Collections group quotations by a primary project or question. Every quotation belongs to exactly
one collection, and Inbox is the permanent default.

## Start in Inbox

The context-menu and keyboard capture paths save directly to Inbox. This makes fast capture
predictable and avoids forcing an organizational decision while reading. Review Inbox later and use
**Edit** to move quotations into named active collections.

## Create and maintain collections

Open **Manage collections**, enter a **New collection name**, and choose **Create collection**.
Choose a collection in the manager to rename it with **Save name**, archive it, restore it, or
delete it. Inbox cannot be renamed, archived, or deleted.

Archive a collection when its work is complete but the research should remain available. Archived
collections are omitted from ordinary results; enable **Include archived** to search them. Restore
the collection when it becomes active again.

Deleting a non-Inbox collection does not delete its quotations. The confirmation explicitly moves
them to Inbox first. This protects saved research while removing the organizational container.

## Pick useful boundaries

Use one collection for the main context in which a quote will be used: a paper, investigation,
design question, or reading project. Use tags for themes that span several collections. Avoid a new
collection for every source unless source-level grouping is the actual workflow; the source host
and title are already searchable.

## Export and recover

With a collection filter active, **Download Markdown** exports only that collection. JSON backup
always preserves the complete library and collection relationships. Before deleting or heavily
reorganizing collections, download a JSON backup.
