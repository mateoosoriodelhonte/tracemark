# TraceMark JSON Backup Format

TraceMark’s importable backup is a UTF-8 JSON document with one strict top-level envelope. It is
intended for recovery and migration through TraceMark’s own **Validate and merge backup** flow,
not as a general-purpose interchange contract. The format is currently version 1; consumers should
check `format` and `version` before relying on its contents.

```json
{
  "format": "tracemark-backup",
  "version": 1,
  "exportedAt": "...",
  "collections": [],
  "highlights": [],
  "aiResults": [],
  "settings": {}
}
```

All top-level fields are required and no unrecognized top-level fields are accepted. `exportedAt`
and record timestamps are ISO date-time strings with an offset. IDs are UUIDs. The importer accepts
at most 10,000 collections, 100,000 highlights, and 100,000 AI results, and rejects JSON text over
20 MB.

## Collections

Each `collections` entry represents a research collection. Its fields are `id`, `schemaVersion`,
`name`, `normalizedName`, `status`, `createdAt`, and `updatedAt`. `schemaVersion` is `1` and
`status` is either `active` or `archived`. `normalizedName` is the normalized search form of the
name; it is part of the stored format and should not be treated as display copy.

Every import must include the canonical active Inbox collection: its ID must be TraceMark’s Inbox
ID, its name must be `Inbox`, and its normalized name must be `inbox`. Collection IDs and normalized
collection names must each be unique within the backup.

## Highlights

Each `highlights` entry is a saved quotation. Required fields are `id`, `schemaVersion`, `quote`,
`prefix`, `suffix`, `title`, `url`, `hostname`, `collectionId`, `tags`, `note`, `searchText`,
`searchTokens`, `createdAt`, and `updatedAt`. `heading`, `context`, and `canonicalUrl` are optional.
The quotation is the exact captured text; prefix and suffix help TraceMark anchor an exact match on
the source page. The source and canonical URL, where present, must be normalized HTTP(S) URLs.

`collectionId` must name a collection in the same envelope. `tags` are strings, while `searchText`
and `searchTokens` are derived fields used by local search. Although these fields are exported,
TraceMark recomputes normalized source, hostname, tags, canonical URL, and search fields during
import rather than trusting them as-is. Highlight IDs must be unique.

## AI results and settings

Each `aiResults` entry has `id`, `schemaVersion`, `kind`, `provider`, `sourceHighlightIds`,
`content`, and `createdAt`; `suggestedTags` is optional. `kind` is `summary`, `explanation`, `tags`,
or `overview`; the exported provider is `ollama`. Each result must refer only to highlights in the
same backup. AI output is stored research data and may include content generated by a local model.

`settings` contains `id` (`settings`), `schemaVersion`, `theme` (`system`, `light`, or `dark`), and
`ai`. The `ai` object contains `provider` (`none` or `ollama`) and a model string. Exporting a
backup does not grant the optional Ollama permission on another browser; browser permissions are
not part of this JSON file.

## Import semantics and safety

TraceMark parses the entire file strictly, validates relationships, then merges inside one IndexedDB
transaction. Same-ID records may be updated when the import is newer; equivalent collections or
highlights can be skipped; colliding IDs may be regenerated while references are remapped. Thus an
import is a merge, not a destructive restore. Invalid or unresolved references fail the import.

Backups contain quotation text, source URLs, notes, tags, and potentially saved AI output. Protect
them as sensitive research. A Markdown export is deliberately separate: it is readable and escaped
for display, but TraceMark cannot import it. For recovery guidance, see
[DATA_LIFECYCLE.md](DATA_LIFECYCLE.md).
